# 第二阶段首轮交付与验收

日期：2026-10-08。状态：本地去重、关系修正、结果页和 AI 辅助调用路径已接通；真实 AI 调用与独立人工标注验收尚未完成，不据此宣布第二阶段最终验收通过。

## 已交付

- 整本有效记录进入分析，涵盖各批次人工修订；原始读取记录不修改。存在读取缺口时，结果明确标为可用部分。
- 同来源跨文件重复、银行与平台付款映射、有明确订单依据的合付、明确退款关联。退款保留原付款与退款两笔真实收付，未找到原付款也不丢弃退款。
- 合并逐字段保留备选值与来源：微信商户、商品说明和银行记账信息均可查看。银行余额与账户标识保留在来源层，不伪造合并余额。
- “去重后流水”页面展示结果、分币种收付与退款、来源详情、可选配对核对；支持确认、拒绝、暂缓、拆开、撤销、显示字段修正与 JSON 导出。
- 人工决定追加保存；输入版本变化使不再成立的接受决定失效，拒绝意图在重复导入扩大来源组后仍保留。分析快照与读取底稿分开保存。
- AI 仅提供候选配对判断，不能单凭模型判断自动减少金额。支持发送预览、进度、取消、失败保留、已完成结果复用和迟到响应丢弃。

## AI 配置与隐私

用户指定 DeepSeek V4.1 Flash，暂不设置总调用或费用上限。官方 API 模型标识采用 `deepseek-flash`，服务为 `https://api.deepseek.com/chat/completions`。不自动替换其他模型。依据：[DeepSeek 官方发布说明](https://api-docs.deepseek.com/news/news260910/)。

在“去重后流水 → AI 辅助配对”中先查看发送内容，再填写本机会话密钥并点击开始。也支持启动前设置 `DEEPSEEK_API_KEY`。密钥不写入项目或分析数据库，不应发送到聊天中。未点击开始不会调用外部服务。每次请求最多 8 个候选，这是分批大小，不是总调用上限；取消不能撤回已经发出的请求。

出站内容采用字段白名单和账本内稳定匿名标识。直接转账对象、账户、订单标识被替换，原始文件、截图、原始字段整表不外发；普通商户及有用消费描述按需保留，明显嵌入的电话、邮箱、地址等会清理。该机制是可检查的首版保护规则，不能声称任意自由文本都已达到完美匿名化。发送预览提供实际出站内容供核对。

本轮未配置密钥、没有真实 AI 调用。已通过模拟服务验证调用、缓存、取消和统计不被 AI 直接改变；官方线上响应兼容性、费用和配对质量仍待实测。

## 当前规则的明确边界

金额使用十进制精确比较；币种、方向、状态与已知账户尾号冲突会阻止配对。金额和时间相同只产生候选。自动采用还要求平台支付渠道及具体商户一致，或银行原文明确包含平台订单标识，并且没有竞争候选。

普通精确时间候选窗口为 300 秒，只有日期时使用同日；强订单标识不受统一短时间窗口机械限制。合付搜索限同平台 2 至 4 单、候选池最多 12 单，总候选保护阈值 1,200；搜索截断会提示并停用当轮付款自动采用，不能假装已覆盖全部可能性。这些是首轮工程参数，不是通用准确率保证。

目前不推断未知来源就是某家银行；折扣、混合支付、缺少渠道或商户依据的情形保守保留。尚不做本人账户转移剔除、生活支出、借贷分类、AA、亲友身份或报销归因。

当前本地规则在访问结果时按有效记录版本更新并缓存整本结果，并非已经实现逐条增量计算。AI 缓存复用的是受保护候选内容相同的判断。
