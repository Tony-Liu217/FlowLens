# 导入与核验边界

## 读取机制

1. 根据文件内容识别格式，读取 CSV、Excel、PDF 表格或图片。
2. 使用有限的字段别名识别日期、金额、方向等列，支持列顺序变化和部分多层表头。
3. 对已知来源结构补充明确的语义约定；不依赖个人账号或文件名匹配。
4. 文本 PDF 无法提取表格或页面为扫描件时，转本地 OCR。OCR 按检测到的表头和位置组合记录，并保留截图和不同识别路径的证据。
5. 对关键字段、方向冲突和页面完整性进行检查，保留无法解决的问题。

对应代码入口：`backend/jiaowopay_ingest/readers.py`、`mapping.py`、`normalize.py`，以及 `backend/jiaowopay_ocr/table.py`、`policy.py`。

## 金额与方向

金额支持常见货币前缀、全半角、点号小数、合法逗号千分位、前置正负号、括号负数及后置负号等。格式不明确、重复符号、方向证据冲突等情况不静默取绝对值放行。

方向优先依据明确收支字段、收入／支出分列、显式金额符号和已知来源约定。未知单金额列的无符号正数不会默认当收入。已知建行文本 PDF 结构可以应用“不带加号的正数为收入”的约定；这不意味着所有未知银行结构都可以这样判断。

币种缺失或未识别目前默认人民币并保留提示，已识别外币分别汇总。裸 `¥` 或 `$` 并不足以唯一确定 ISO 币种；请核对外币来源。当前不提供自动汇率转换。

## 格式变化会怎样

| 变化 | 当前边界 |
| --- | --- |
| 列顺序变化，增加不冲突的无关列 | 通用映射通常可适应 |
| 已知别名、空白和全半角变化 | 通常可规范化识别 |
| 陌生字段名、复杂合并表头 | 可能无法识别或产生歧义 |
| 来源标题或关键结构字段变化 | 可能退回通用映射，失去来源特定的方向依据 |
| 表头不变，但正负数的业务视角变化 | 可能继续套用旧规则，现有系统不能保证自动发现 |
| 文本账单改为扫描件 | OCR 的表头和日期能力与文本读取不同，不能保证同样成功 |

后端有显式映射配置能力，但工作台目前没有让用户交互式保存新模板的完整流程。文件级格式未识别时，补录几条记录不能证明整份文件已完整读取。

## 复核为什么仍然必要

OCR 多种视图可能同时犯错，高识别分数也不是经过校准的正确概率。金额、方向、日期存在关键疑点时需要核验；只有余额存在参考性疑点时，不再要求逐条确认。

荧光标记来自字段错误或 OCR 关键证据，用于定位检查位置。无法定位到单个字段的问题保留在读取说明或页面任务中。未标记不等于全部内容已经验证正确。

OCR 尝试核对可识别的本页笔数，没有可靠笔数时保留整页核验。文本 PDF 目前没有普适的总收支、总笔数自动对账，表外交易遗漏检查也不覆盖所有排版。因此本项目不宣称已适配所有银行或具有统一准确率。

## 如何反馈问题

记录来源、导出方式、文件类型、错误提示及预期行为。优先提供脱敏表头和合成最小示例，移除姓名、账号、流水号、交易对象及私人金额。完整账单、数据库、带访问凭证的启动链接和证据截图不要上传到公开 Issue。

每批最多 20 个文件，合计 50 MiB；PDF 读取上限为 300 页。建议按账期合理分批，同一账本可持续追加。
